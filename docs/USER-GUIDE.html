Dùng Sol đúng lúc, dùng flock để điều phối

1. Ai chịu trách nhiệm việc gì?

Kiến trúc chỉ tiết kiệm chi phí khi ranh giới quyền lực rõ ràng. Worker rẻ hơn được phép viết code, nhưng không được tự định nghĩa thành công hay tự phê duyệt kết quả.

Planner & reviewer

Sol

Đọc policy, chốt mục tiêu nhỏ, viết tiêu chí nghiệm thu, gọi agentctl, rồi review task + patch + evidence đã đóng băng.

Implementer

OpenCode / DeepSeek

Chỉ thi công task đã khóa trong workspace của run. Lời tự báo cáo và câu “tests passed” của worker không phải bằng chứng.

Control plane

agentctl + verifier

Tạo clone độc lập, chụp Git diff, khóa SHA-256, kiểm tra scope/ngân sách, chạy validation argv và điều khiển state machine.

Authority

Con người

Cho phép chạy không sandbox, duyệt thay đổi rủi ro cao, kiểm tra worktree cuối, commit, push, merge và deploy theo quy trình project.

Quy tắc an toàn quan trọng nhất

Permission của OpenCode chỉ là lớp phòng vệ bổ sung, không phải OS sandbox. Process OpenCode chạy trực tiếp vẫn có quyền của user hệ điều hành. Muốn chạy unattended, hãy bọc toàn bộ worker trong container, VM hoặc sandbox cấp hệ điều hành thật.

    Tuỳ chọn khác:

    python3.11 -m pip install -e "$ACP_ROOT"
agentctl version --json

  3. Hỏi tool về đường dẫn thật

3. Cấu hình OpenCode + DeepSeek đúng cách

Project chỉ biết tên profile ngữ nghĩa như default-implementer. Model, CLI và credential nằm trong user config bên ngoài project.

3.1 Cài, đăng nhập và xác nhận model

opencode --version
opencode auth login
opencode auth list
opencode models --refresh
opencode models

Chép đúng chuỗi provider/model mà opencode models in ra. Tên “DeepSeek V4 Pro” là yêu cầu năng lực, không bảo đảm là model ID trên mọi phiên bản/provider. Không coi model ID trong template là giá trị chắc chắn tồn tại.

Tài liệu chính thức:

  • Cài đặt và bắt đầu với OpenCode
  • OpenCode CLI: auth, models, run và flags
  • Cấu hình provider/model
  • Tạo agent OpenCode riêng bằng Markdown
  • Permission của OpenCode

3.2 Tạo user worker profile

Chép templates/user-config.toml tới đường dẫn user_config từ agentctl paths, rồi thay model placeholder bằng ID vừa xác nhận:

schema_version = 1

[worker_profiles.default-implementer]
adapter = "generic-cli"
runtime_id = "opencode-deepseek-worker"
isolation = "unsafe-host"
argv = [
  "opencode", "run",
  "--format", "json",
  "--model", "provider/model-confirmed-by-opencode-models",
  "--agent", "agentctl-worker",
  "--dir", "{workspace}",
  "{prompt}"
]
probe_argv = ["opencode", "models"]
probe_contains = "provider/model-confirmed-by-opencode-models"
env_allow = ["HOME", "XDG_CONFIG_HOME", "DEEPSEEK_API_KEY"]
timeout_seconds = 1500
max_output_bytes = 8000000
prompt = "Read the request contract at {request_file}, then read every task.context_files entry. Implement only its bounded objective. Do not commit, push, access external paths, or change the contract. Leave the workspace ready for controller verification."
  • Giữ API key trong auth store của OpenCode hoặc environment của process.
  • env_allow chỉ liệt kê tên biến cần truyền; tuyệt đối không ghi giá trị secret vào TOML/JSON/prompt.
  • Controller lọc environment và redact giá trị của các biến được liệt kê khỏi stdout/stderr; đây không phải cơ chế cô lập secret.
  • probe_argv liệt kê model và probe_contains phải khớp chính xác model ID dùng trong --model. Điều này vẫn không chứng minh auth/network/sandbox sẽ hoạt động ở lúc generation.

3.3 Permission: lớp phụ, không phải sandbox

Cài deny-first policy đi kèm thành agent OpenCode toàn cục. Theo quy ước của OpenCode, tên file Markdown trở thành tên agent, nên lệnh dưới đây tạo đúng agent agentctl-worker đã dùng trong worker profile:

mkdir -p "$HOME/.config/opencode/agents"
cp "$ACP_ROOT/templates/opencode-agent.md" \
  "$HOME/.config/opencode/agents/agentctl-worker.md"

Template chỉ cho phép đọc/sửa trong workspace cùng một số lệnh git status/git diff; nó deny external directory, web, task/subagent, skill và các bash command khác. Có thể đặt bản riêng tại .opencode/agents/agentctl-worker.md, nhưng bản global giúp policy runtime nằm ngoài patch surface của project được gắn.

Không dùng --auto cho worker chạy trực tiếp trên host

Theo tài liệu OpenCode, --auto tự chấp thuận các yêu cầu permission không bị deny rõ ràng. Quy tắc deny vẫn hữu ích, nhưng lỗi cấu hình permission có thể mở quyền ngoài dự kiến.

Kiểm tra permission hiệu lực của đúng agent được truyền qua --agent. OpenCode gộp permission riêng của agent với global config và rule riêng có thể override rule global; tốt nhất dùng một agent worker chuyên biệt với deny policy rõ ràng.

3.4 Hai chế độ isolation

Khuyến nghị

external-sandbox

Chỉ dùng khi argv thật sự đi vào container/VM/OS sandbox trước khi chạy OpenCode. Nhãn này là khai báo; agentctl không tự dựng và không xác minh sandbox.

Opt-in thủ công

unsafe-host

Dùng cho OpenCode chạy trực tiếp. Mỗi run phải được người dùng cho phép rõ ràng bằng run init --allow-unsafe-worker. Flag chỉ xác nhận chấp nhận rủi ro, không làm process an toàn hơn.

Validation có khai báo riêng trong .agentctl.toml: validation_isolation. Nếu là unsafe-host, mỗi lần verify cần --allow-unsafe-validation. Validator chạy code ứng viên và có thể tải dependency/network nếu argv của project yêu cầu, vì vậy cũng cần sandbox thật cho unattended execution.

4. Gắn module vào một project

project attach tạo đúng một file .agentctl.toml. Nó không tự commit và không ghi đè config đã có.

  1. Inspect và dry-run

    "$ACP" project inspect --project /absolute/path/to/project --json
"$ACP" project attach --project /absolute/path/to/project --dry-run --json

  2. Tạo adapter phù hợp project

    Sao chép templates/project.toml, rồi chỉnh:

    • project_id và tên worker_profile;
    • file chỉ dẫn/context cần được worker đọc;
    • protected path, high-risk path, số file/dòng, patch bytes, số vòng sửa;
    • validation profile, path match, cwd, argv, env và timeout;
    • validation_isolation đúng với cách validator thật sự chạy.
    "$ACP" project attach \
  --project /absolute/path/to/project \
  --template /absolute/path/to/project-adapter.toml \
  --dry-run --json

  3. Attach thật

    "$ACP" project attach \
  --project /absolute/path/to/project \
  --template /absolute/path/to/project-adapter.toml --json

  4. Human review và commit adapter

    Người dùng kiểm tra .agentctl.toml và mọi file instruction/context, sau đó commit chúng vào project. Các lệnh Git sau là trách nhiệm của người dùng, không phải thao tác mà agentctl thực hiện:

    git status --short
sed -n '1,260p' .agentctl.toml
git diff -- AGENTS.md
git add .agentctl.toml AGENTS.md
git diff --cached
git commit -m "chore: attach ducking"

    run init đòi worktree sạch, base_sha bằng HEAD, và mọi context bắt buộc đã nằm trong commit gốc. Vì vậy attach xong nhưng chưa commit thì chưa chạy task được.

  5. Doctor

    "$ACP" doctor --project /absolute/path/to/project --json

    doctor kiểm tra config, cleanliness, context trong base, executable của validator và worker probe. Hai declaration unsafe-host luôn được báo non-green có chủ đích; chỉ tiếp tục sau khi hiểu và cho phép các unsafe flag tương ứng.

Detach có điều kiện

project detach chỉ xóa config chưa bị sửa kể từ lúc attach, có receipt, và không có run đang active. Evidence cũ vẫn được giữ. Luôn dùng --dry-run trước.

6. Flock MVP lấy cảm hứng từ OTP

Flock thêm lớp điều phối nhiều unit nhưng không phải Erlang/OTP, không phải daemon và không tự sinh sáu process. State machine xác định scheduling, lease, retry và terminal state; model chỉ được chọn một lệnh semantic đã được controller cho phép.

Deterministic

RuntimeSupervisor

Giữ flock state, coordinator epoch, sweep lease, alert, restart intensity, cancel và escalation. Đây là vai trò trong controller/state bền vững, không phải phiên chat sống lâu.

Deterministic

MotherRuntime

Khi gọi flock tick, ghép task đã sẵn sàng theo dependency với slot đang rảnh. Nó chỉ schedule, không đưa ra quyết định sản phẩm.

Fixed pool

Đúng sáu slot logic

Mọi flock luôn có slot 0–5. Plan không đổi kích thước pool. Đây là trần lease logic, không bảo đảm sáu process chạy đồng thời; external runner và max_parallel của child project có thể thấp hơn.

Semantic

DeepSeek mother + top

Hai role dùng invocation mới, stateless, chỉ đọc snapshot đã giới hạn. Sol không nằm trong normal loop; Sol chỉ nhận senior escalation hoặc aggregate final review.

MotherRuntime khác semantic mother

MotherRuntime là scheduler xác định trong Python. Semantic mother là DeepSeek được gọi cho soft stall hoặc failure mơ hồ và chỉ được chọn một command trong allowlist.

6.1 Cấu hình supervisor ngoài project

User config phải ánh xạ cả hai semantic role tới profile đã tồn tại. Template đi kèm cố ý dùng cùng một DeepSeek profile:

[semantic_roles]
mother = "deepseek-supervisor"
top = "deepseek-supervisor"

Cài deny-first agent đúng tên được dùng trong profile:

mkdir -p "$HOME/.config/opencode/agents"
cp "$ACP_ROOT/templates/opencode-supervisor-agent.md" \
  "$HOME/.config/opencode/agents/agentctl-supervisor.md"

Mỗi dispatch tạo workspace mới chỉ chứa canonical snapshot tối đa 16 KiB. Snapshot không chứa prior conversation, worker transcript, heartbeat summary, worker prose khác hay raw log. Child worker profile và cả hai semantic profile được probe, đóng băng và hash khi tạo flock; không có model fallback. Provider/model ID, argv và credential vẫn chỉ nằm trong user config/environment, không nằm trong plan.

Semantic supervisor cũng cần sandbox

Nếu child worker là unsafe-host, flock init cần --allow-unsafe-worker. Nếu mother/top là unsafe-host, init cần --allow-unsafe-supervisor và mỗi supervisor dispatch sau đó vẫn cần flag này. Các flag là opt-in riêng cho từng invocation; permission read-only của OpenCode không thay thế container/VM/OS sandbox thật.

6.2 Tạo plan và khởi tạo flock

Bắt đầu từ templates/plan.json. Flock plan dùng contract_version: 2 và cần plan_id, base_sha, goal, danh sách units; task contract lồng bên trong vẫn là version 1. Mỗi unit có depends_on, dùng cùng base SHA và dependency graph không được có chu kỳ. Có thể đặt policy:

"retry": {"max_attempts": 3, "delays_seconds": [5, 30]},
"lease": {
  "liveness_soft_seconds": 45,
  "liveness_hard_seconds": 90,
  "progress_soft_seconds": 120,
  "progress_hard_seconds": 600
}

Pool luôn là sáu slot, không phải field trong plan. budget.wall_seconds của mỗi unit được tính cộng dồn qua các attempt; hết wall budget sẽ dead-letter dù vẫn còn attempt. Worktree phải sạch, base_sha phải đúng HEAD, và flock init phải probe thành công cả mother/top runtime trước khi đóng băng profile + hash:

"$ACP" flock init --project /absolute/path/to/project \
  --plan /absolute/path/to/plan.json --json

# Đặt FLOCK_ID bằng flock_id vừa trả về.
"$ACP" flock status --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --json
"$ACP" supervisor profiles --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --json

Nếu cả child worker và semantic profiles chạy trực tiếp trên host, chỉ sau human authorization mới dùng:

"$ACP" flock init --project /absolute/path/to/project \
  --plan /absolute/path/to/plan.json \
  --allow-unsafe-worker --allow-unsafe-supervisor --json

Hai flag init không thay thế gate riêng của child run init, validator hoặc từng semantic dispatch. Với external sandbox thật, bỏ flag tương ứng.

"$ACP" flock tick --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --json
Không nhầm assignment với execution

tick ghi lease vào state và trả assignment gồm task, slot, incarnation, lease ID và branch_ref. Nó chưa gọi worker hay chạy test. External runner phải giữ mapping lease ↔ child run_id, serialize nguyên task được trả về ngoài project rồi gọi run init → unit dispatch → unit verify. Ở lần dispatch đầu, controller tạo nhánh ducking/... bên trong clone nông độc lập của duck; không tạo branch trong source repo và không chia sẻ Git metadata với duck khác. depends_on chỉ chặn thời điểm cấp lease, không tự áp patch upstream vào base của unit downstream; cho tới khi có assembly/rebase bên ngoài, các unit phụ thuộc phải độc lập về patch hoặc operator phải quản lý handoff này.

Child low-risk có thể báo Flock success ở ready_for_review hoặc accepted. Child high-risk phải tiếp tục qua per-child review human_required và human approval gắn hash đến state accepted trước khi báo success.

Trước heartbeat hợp lệ đầu tiên, gọi flock tick lại sẽ trả đúng assignment/lease cũ với replayed: true, không tạo lease mới. Runner phải persist mapping lease → child run và dedupe theo lease ID trước khi heartbeat; replay không được khởi chạy child thứ hai.

Trong lúc child run chạy, gửi heartbeat. Heartbeat đầu cũng acknowledge assignment. Cùng progress-seq, phase và summary chỉ làm mới liveness; sequence tăng mới làm mới progress. Sequence lùi hoặc cùng sequence nhưng nội dung khác sẽ bị từ chối:

"$ACP" flock heartbeat --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --slot 0 --lease "$LEASE_ID" \
  --progress-seq 1 --phase verifying \
  --summary "focused validators running" --json

Summary chỉ là diagnostic prose không đáng tin trong runtime state; nó không đi vào semantic snapshot của mother, top hay Sol. Sau khi child đủ điều kiện — low-risk ở ready_for_review/accepted, hoặc high-risk ở accepted — đóng attempt bằng EOF gắn đúng child run:

"$ACP" flock finish --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --slot 0 --lease "$LEASE_ID" \
  --outcome succeeded --reason child_run_verified \
  --run "$CHILD_RUN_ID" \
  --json

Với success, controller kiểm tra project/base/config, exact flock_attempt lease envelope, child state, task, patch và green evidence. Nó re-hash task/patch/evidence, tự tạo một Flock-owned review pack mới rồi retain đúng các byte và digest do controller derive dưới flock store. Với child accepted, nó còn validate/retain review và human approval nếu high-risk. Không dùng --artifact cho success — caller-supplied digest bị từ chối. Các outcome khác là retryable_failure, fatal_failure và cancelled; chúng không dùng --run và có thể kèm hash diagnostic. Mỗi attempt có attempt EOF; task terminal có đúng một task EOF.

6.4 Lease, leaf replacement, aggregate drain và DLQ

Gọi sweep theo timer bên ngoài:

"$ACP" flock sweep --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --json
Sự kiệnController làm gì?Phạm vi
Soft liveness/progress expiryĐánh dấu soft_stalled, tạo snapshot cho mother chọn wait, recycle hoặc notify_topMột task
Hard expiryTạo attempt EOF với worker_eof_seen: false, vào bounded retryThay đúng một slot
Crash/transient/controller lossCho phép retry tự động nếu còn attempt; delay mặc định 5/30 giâyMột task
Fatal/exhausted/dead-letterGhi trigger terminal, escalate, fence mọi sibling lease và cho mọi task chưa xong terminal EOFCả flock
> 6 restart / 60 giâyMở pool circuit, drain toàn aggregate rồi chuyển anomaly lên topCả flock

Chỉ leaf failure còn retryable và chưa chạm circuit mới là one-for-one: slot đó tăng incarnation, còn sibling lease hợp lệ tiếp tục. Child tự báo cancelled sẽ escalate và drain flock; dùng flock cancel cho chủ ý huỷ toàn aggregate. Fatal, hết attempt/budget, explicit dead-letter hoặc pool/root circuit cũng là aggregate escalation: controller fence/drain mọi sibling lease đang sống và tạo terminal EOF cho mọi task chưa xong. Lease bind ID, coordinator epoch, slot và incarnation nên heartbeat/EOF đến trễ từ occupant cũ bị trả stale_lease. “DLQ” trong MVP là task EOF bền vững ở trạng thái dead_lettered cùng alert/outbox; không có message broker riêng.

Root recovery là trường hợp riêng, không phải leaf one-for-one. Chỉ sau khi external runtime đã dừng controller process cũ, đọc coordinator_epoch từ flock status rồi fence đúng generation đó bằng operation ID ổn định:

"$ACP" flock recover --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --expected-epoch "$EXPECTED_EPOCH" \
  --operation-id recover-controller-1 \
  --reason coordinator_lost --json

recover không kill process. Nó đóng các lease active với lý do controller_lost, tăng coordinator epoch, cho sáu-slot subtree retry ở generation mới và re-issue semantic obligation của task không bị fence. Trong final_review, recovery là no-op idempotent và giữ nguyên review handoff. Retry cùng operation ID trả lại kết quả đã ghi; operation mới với expected epoch cũ bị stale_recovery. Quá ba root recovery trong 60 giây mặc định sẽ mở root circuit, escalate và drain toàn bộ sibling lease/task chưa xong. Không gọi lệnh này khi chưa chứng minh process cũ đã dừng, và không đổi operation ID chỉ để lách epoch mismatch.

6.5 Dispatch DeepSeek stateless và chỉ đánh thức Sol khi cần

Mỗi lệnh supervisor dispatch xử lý tối đa một snapshot pending của role:

"$ACP" supervisor next --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --role mother --json

"$ACP" supervisor dispatch --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --role mother \
  --allow-unsafe-supervisor --json

"$ACP" supervisor dispatch --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --role top \
  --allow-unsafe-supervisor --json

Mỗi lần dispatch atomically claim đúng một pending snapshot trước khi gọi model, nên dispatcher đồng thời không thể lặp cùng một semantic call. Delivery lỗi được thử tối đa ba lần với backoff 5 rồi 30 giây; lần thứ ba thất bại sẽ exhaust item, escalate Flock và mở event cho Sol. Claim hết hạn có thể được lấy lại, còn kết quả từ claimant cũ bị từ chối.

Mother có thể chọn các command được offer như wait, recycle, retry_task, dead_letter, notify_top hoặc no-op. Top chỉ có ack, escalate_sol và open_final_review khi mọi unit đã thành công và được báo cáo; Top không được abort_flock. Với retry_wait mơ hồ, ack của Top hoặc Sol sẽ authorize attempt hữu hạn tiếp theo. Action phải bind đúng snapshot ID, SHA-256, claim, command ID, subject revision, Flock revision, coordinator epoch và state; command tự thêm, claim cũ hoặc decision cũ phải fail closed.

Sol không được dispatch như external profile. Khi top mở escalation/final review, Codex/Sol control session poll:

"$ACP" supervisor next --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --role sol --json

Escalation offer ack hoặc abort_flock; aggregate final review offer approve_flock, rework hoặc abort_flock. Sol phải review task, patch, evidence và Flock-owned review pack đã đóng băng của các child run trước khi chọn và dùng supervisor apply --file action.json; action vẫn phải bind đúng command được snapshot offer. approve_flock re-hash toàn bộ retained artifact set rồi chuyển aggregate state sang reviewed, không phải complete. Nó không accept/integrate từng child và không apply patch; hai lựa chọn còn lại đi vào escalation.

6.6 Dashboard thời gian thực

"$ACP" flock dashboard --project /absolute/path/to/project \
  --flock "$FLOCK_ID" --port 8765 \
  --allow-unsafe-supervisor

Mở http://127.0.0.1:8765/ để xem live sáu duck slot, lease, heartbeat/progress age, task budget, semantic outbox, anomaly và durable timeline. Dashboard cập nhật mỗi giây bằng SSE; có thể gọi tick, sweep, huỷ aggregate sau khi nhập đúng flock ID, và dispatch một Mother/Top event sau khi xác nhận token cost.

Control plane cục bộ, không phải process runner.

Server chỉ bind loopback và action dùng token ngẫu nhiên theo process. Bỏ --allow-unsafe-supervisor nếu chỉ muốn quan sát; nút DeepSeek sẽ bị khoá. Dashboard không launch child, không ghép patch và không làm Sol polling.

6.7 Giới hạn MVP và ví dụ chi phí cache

Chưa có combined patch pipeline

Khi một child báo success bằng --run, Flock tự kiểm tra và giữ nguyên byte của task, patch, evidence, đồng thời tạo/giữ Flock-owned review pack cùng các digest do controller derive. Child accepted còn đóng góp review đã validate và human approval nếu cần.     "$ACP" decision approve-human \

    "$ACP" integrate \

Không commit. Không push. Không merge. Không deploy. Nó có thể áp patch vào worktree khi nhận --apply, và validator có thể chạy bất kỳ argv nào project đã cấu hình — vì thế phải review config và isolation trước.

10. Doctor và xử lý sự cố

dirty_worktree, config_in_base: false, context_not_in_base

Adapter/context chưa được commit hoặc worktree còn thay đổi. Human xác định chính xác thay đổi cần giữ, commit chúng, lấy HEAD mới và tạo lại task. Không tự reset hay xoá việc của người khác.

worker_profile_not_found hoặc worker_unavailable

Đồng bộ tên profile giữa .agentctl.toml và user config; kiểm tra path từ agentctl paths, PATH, probe_argv, Python/OpenCode. Có thể dùng --user-config /path/config.toml khi cần config khác.

Probe xanh nhưng model/provider vẫn lỗi

Probe template chạy unfiltered opencode models và kiểm tra probe_contains. Chạy thêm opencode auth list và opencode models --refresh, rồi chép chính xác ID do runtime in. Doctor không xác minh auth, network hay chất lượng sandbox.

unsafe_worker_requires_opt_in / unsafe_validation_requires_opt_in

Đây là gate chủ ý. Tốt nhất dựng external sandbox. Nếu child profile của Flock là unsafe-host, flock init cần --allow-unsafe-worker; mỗi child run init và validator vẫn có gate riêng. Nếu human chấp nhận host execution, thêm đúng flag ở đúng bước. Flag không tăng mức cô lập.

unsafe_supervisor_requires_opt_in hoặc semantic dispatch lỗi

semantic_supervisor_unavailable ở flock init nghĩa là probe mother/top profile thất bại; sửa executable, model ID, auth hoặc sandbox wrapper trước. Với profile unsafe-host, init cần --allow-unsafe-supervisor và mỗi dispatch sau đó vẫn cần flag này sau human authorization. Với semantic_invalid_response, stale_decision hoặc invalid_semantic_command, không tự sửa hash/command: giữ snapshot pending và dispatch lại bằng invocation stateless bind đúng snapshot, claim, hash, command, revisions, epoch và state. Delivery chỉ có ba attempt với backoff 5/30 giây; exhaustion tự escalate sang Sol. Top không có quyền abort.

stale_lease, progress collision hoặc Flock bị stall

External runner phải dùng đúng tuple flock/slot/lease/incarnation từ assignment mới nhất. Assignment có replayed: true trước heartbeat đầu tiên phải reuse mapping đã persist, không launch child thứ hai; persist và deduplicate trước, heartbeat sau. Không nhận heartbeat/EOF trễ từ process cũ. Gọi flock status, chạy flock sweep theo timer, drain mother/top outbox, rồi flock tick lại khi retry đã được authorize và delay đã hết.

unverified_child_result, child_not_ready_for_review, human_gate_required hoặc success EOF mismatch

Không thay --run bằng digest tự ghi. Hoàn tất đúng child run đã bind lease: low-risk cần green verification ở ready_for_review/accepted; high-risk phải qua per-child human gate đến accepted. Giữ nguyên run store rồi gọi lại flock finish --run CHILD_RUN_ID. Success không nhận --artifact; controller re-hash task/patch/evidence, tự tạo Flock-owned review pack và retain các artifact.

stale_recovery

Dừng và xác minh controller generation đang sống. Đọc epoch hiện tại từ flock status, rồi recover bằng đúng --expected-epoch và một --operation-id ổn định. Retry operation đã ghi bằng cùng ID; không đổi ID để lách stale epoch.

unknown_validation_profile / no_profiled_validation_for_path

Task yêu cầu profile chưa tồn tại, hoặc file thay đổi không được command nào trong profile bao phủ. Sửa task/config ở một base mới thay vì bỏ qua validation.

verify_failed

Mở evidence.json và log path/hash trong run root. Nếu là lỗi cơ học có phạm vi rõ và còn budget, dispatch lại; controller tự đưa evidence lỗi vào repair context. Không tạo review pack khi evidence chưa xanh.

config_drift, patch_drift, artifact_tampered, review_mismatch

Dừng ngay. Không sao chép/sửa hash để vượt gate. Khôi phục artifact đúng hoặc tạo run mới từ base sạch. Mọi thay đổi patch làm review cũ mất hiệu lực.

base_sha_drift khi integrate

HEAD project đã khác commit được review. Không áp patch cũ lên base mới; tạo task/run mới để evidence và decision gắn đúng code hiện tại.

Timeout, output limit hoặc exit code 127

Dùng run status --run lấy run_root, đọc worker/verifier result và log. Exit 127 thường là executable không có; timeout/output limit cần thu nhỏ task hoặc sửa runtime/command. Không coi log thiếu là pass.

Báo lỗi mà không làm lộ secret

Gửi error code, run ID, base SHA, patch SHA và tên check thất bại. Không gửi API key, auth store, raw environment hay log chưa kiểm tra.

11. Checklist trước khi bấm chạy

  • Project adapter và mọi instruction/context đã được human review + commit.
  • Worktree sạch; task base SHA đúng bằng HEAD.
  • Model ID được xác nhận bằng opencode models, không đoán theo tên marketing.
  • Credential nằm ngoài repository/task/prompt.
  • Worker và validator có sandbox thật; nếu không, human đã cho phép rõ hai unsafe flag.
  • OpenCode permission chặn external directory, commit/push và capability không cần thiết.
  • Task có một objective, đường dẫn hẹp, tiêu chí có proof và budget hữu hạn.
  • Flock plan có DAG hợp lệ; profile unsafe đã được authorize riêng bằng --allow-unsafe-worker / --allow-unsafe-supervisor ở init và vẫn qua các gate invocation sau.
  • External runner persist lease ↔ child run, deduplicate assignment replay trước heartbeat và không hiểu tick là execution.
  • Heartbeat tăng sequence chỉ khi có progress; sweep và mother/top dispatch có timer bên ngoài.
  • Semantic supervisor stateless, snapshot-only, không nhận heartbeat summary; dispatch dùng claim, tối đa ba attempt với backoff 5/30 giây rồi escalate Sol.
  • Success EOF dùng flock finish --run CHILD_RUN_ID; high-risk child đã qua human gate đến accepted; không truyền --artifact.
  • Sol chỉ review frozen pack và mọi decision gắn đúng hash.
  • Với Flock, Sol chỉ được gọi tại escalation/final review; approve_flock tạo state reviewed, chưa ghép patch, aggregate verify, accept child hay integrate.
