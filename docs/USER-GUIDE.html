Protocol v1 · Agent Control Plane

Dùng Sol để suy nghĩ, dùng worker để thi công

Hướng dẫn vận hành module agentctl: Sol lập kế hoạch và review ngữ nghĩa, OpenCode/DeepSeek xử lý task nhỏ trong workspace riêng, còn máy kiểm chứng giữ patch, hash, ngân sách và trạng thái. Người dùng vẫn nắm quyền đối với rủi ro và Git.

Kết quả cuối của agentctl là một patch đã kiểm chứng.

Nó không commit, push, merge hay deploy. Ngay cả integrate --apply cũng chỉ áp patch vào worktree sạch.

1. Ai chịu trách nhiệm việc gì?

Kiến trúc chỉ tiết kiệm chi phí khi ranh giới quyền lực rõ ràng. Worker rẻ hơn được phép viết code, nhưng không được tự định nghĩa thành công hay tự phê duyệt kết quả.

Planner & reviewer

Sol

Đọc policy, chốt mục tiêu nhỏ, viết tiêu chí nghiệm thu, gọi agentctl, rồi review task + patch + evidence đã đóng băng.

Implementer

OpenCode / DeepSeek

Chỉ thi công task đã khóa trong workspace của run. Lời tự báo cáo và câu “tests passed” của worker không phải bằng chứng.

Control plane

agentctl + verifier

Tạo clone độc lập, chụp Git diff, khóa SHA-256, kiểm tra scope/ngân sách, chạy validation argv và điều khiển state machine.

Authority

Con người

Cho phép chạy không sandbox, duyệt thay đổi rủi ro cao, kiểm tra worktree cuối, commit, push, merge và deploy theo quy trình project.

Quy tắc an toàn quan trọng nhất

Permission của OpenCode chỉ là lớp phòng vệ bổ sung, không phải OS sandbox. Process OpenCode chạy trực tiếp vẫn có quyền của user hệ điều hành. Muốn chạy unattended, hãy bọc toàn bộ worker trong container, VM hoặc sandbox cấp hệ điều hành thật.

2. Cài module và xác định đường dẫn

Module cần Python 3.11+ và không có dependency Python lúc runtime. Có thể chạy ngay từ source hoặc cài editable.

  1. Clone repository

    git clone git@github.com:TruongPhuHung/ducking.git agent-control-plane
cd agent-control-plane
./scripts/agentctl version --json

    Nếu repository là private, SSH key của GitHub phải được cấu hình trước.

  2. Chọn một cách gọi ổn định

    ACP_ROOT=/absolute/path/to/agent-control-plane
ACP="$ACP_ROOT/scripts/agentctl"
"$ACP" version --json

    Launcher tự tìm Python 3.13/3.12/3.11, Python bundle của Codex, rồi mới thử python3. Nếu cần, đặt AGENTCTL_PYTHON trỏ tới interpreter Python 3.11+.

    Tuỳ chọn khác:

    python3.11 -m pip install -e "$ACP_ROOT"
agentctl version --json

  3. Hỏi tool về đường dẫn thật

    "$ACP" paths --json

    Không đoán đường dẫn config/state. Tool ưu tiên các biến sau:

    Dữ liệuƯu tiên 1Mặc định
    User configAGENTCTL_CONFIG$XDG_CONFIG_HOME/agent-control-plane/config.toml, hoặc ~/.config/agent-control-plane/config.toml
    Run stateAGENTCTL_STATE_HOME$XDG_STATE_HOME/agent-control-plane, hoặc ~/.local/state/agent-control-plane
State nằm ngoài project

Task đã khóa, patch, evidence, event log, worker log, verifier clone và attachment receipt đều nằm trong state home; không đưa thư mục này vào Git của ứng dụng.

3. Cấu hình OpenCode + DeepSeek đúng cách

Project chỉ biết tên profile ngữ nghĩa như default-implementer. Model, CLI và credential nằm trong user config bên ngoài project.

3.1 Cài, đăng nhập và xác nhận model

opencode --version
opencode auth login
opencode auth list
opencode models --refresh
opencode models

Chép đúng chuỗi provider/model mà opencode models in ra. Tên “DeepSeek V4 Pro” là yêu cầu năng lực, không bảo đảm là model ID trên mọi phiên bản/provider. Không coi model ID trong template là giá trị chắc chắn tồn tại.

Tài liệu chính thức:

  • Cài đặt và bắt đầu với OpenCode
  • OpenCode CLI: auth, models, run và flags
  • Cấu hình provider/model
  • Tạo agent OpenCode riêng bằng Markdown
  • Permission của OpenCode

3.2 Tạo user worker profile

Chép templates/user-config.toml tới đường dẫn user_config từ agentctl paths, rồi thay model placeholder bằng ID vừa xác nhận:

schema_version = 1

[worker_profiles.default-implementer]
adapter = "generic-cli"
runtime_id = "opencode-deepseek-worker"
isolation = "unsafe-host"
argv = [
  "opencode", "run",
  "--format", "json",
  "--model", "provider/model-confirmed-by-opencode-models",
  "--agent", "agentctl-worker",
  "--dir", "{workspace}",
  "{prompt}"
]
probe_argv = ["opencode", "models"]
probe_contains = "provider/model-confirmed-by-opencode-models"
env_allow = ["HOME", "XDG_CONFIG_HOME", "DEEPSEEK_API_KEY"]
timeout_seconds = 1500
max_output_bytes = 8000000
prompt = "Read the request contract at {request_file}, then read every task.context_files entry. Implement only its bounded objective. Do not commit, push, access external paths, or change the contract. Leave the workspace ready for controller verification."
  • Giữ API key trong auth store của OpenCode hoặc environment của process.
  • env_allow chỉ liệt kê tên biến cần truyền; tuyệt đối không ghi giá trị secret vào TOML/JSON/prompt.
  • Controller lọc environment và redact giá trị của các biến được liệt kê khỏi stdout/stderr; đây không phải cơ chế cô lập secret.
  • probe_argv liệt kê model và probe_contains phải khớp chính xác model ID dùng trong --model. Điều này vẫn không chứng minh auth/network/sandbox sẽ hoạt động ở lúc generation.

3.3 Permission: lớp phụ, không phải sandbox

Cài deny-first policy đi kèm thành agent OpenCode toàn cục. Theo quy ước của OpenCode, tên file Markdown trở thành tên agent, nên lệnh dưới đây tạo đúng agent agentctl-worker đã dùng trong worker profile:

mkdir -p "$HOME/.config/opencode/agents"
cp "$ACP_ROOT/templates/opencode-agent.md" \
  "$HOME/.config/opencode/agents/agentctl-worker.md"

Template chỉ cho phép đọc/sửa trong workspace cùng một số lệnh git status/git diff; nó deny external directory, web, task/subagent, skill và các bash command khác. Có thể đặt bản riêng tại .opencode/agents/agentctl-worker.md, nhưng bản global giúp policy runtime nằm ngoài patch surface của project được gắn.

Không dùng --auto cho worker chạy trực tiếp trên host

Theo tài liệu OpenCode, --auto tự chấp thuận các yêu cầu permission không bị deny rõ ràng. Quy tắc deny vẫn hữu ích, nhưng lỗi cấu hình permission có thể mở quyền ngoài dự kiến.

Kiểm tra permission hiệu lực của đúng agent được truyền qua --agent. OpenCode gộp permission riêng của agent với global config và rule riêng có thể override rule global; tốt nhất dùng một agent worker chuyên biệt với deny policy rõ ràng.

3.4 Hai chế độ isolation

Khuyến nghị

external-sandbox

Chỉ dùng khi argv thật sự đi vào container/VM/OS sandbox trước khi chạy OpenCode. Nhãn này là khai báo; agentctl không tự dựng và không xác minh sandbox.

Opt-in thủ công

unsafe-host

Dùng cho OpenCode chạy trực tiếp. Mỗi run phải được người dùng cho phép rõ ràng bằng run init --allow-unsafe-worker. Flag chỉ xác nhận chấp nhận rủi ro, không làm process an toàn hơn.

Validation có khai báo riêng trong .agentctl.toml: validation_isolation. Nếu là unsafe-host, mỗi lần verify cần --allow-unsafe-validation. Validator chạy code ứng viên và có thể tải dependency/network nếu argv của project yêu cầu, vì vậy cũng cần sandbox thật cho unattended execution.

4. Gắn module vào một project

project attach tạo đúng một file .agentctl.toml. Nó không tự commit và không ghi đè config đã có.

  1. Inspect và dry-run

    "$ACP" project inspect --project /absolute/path/to/project --json
"$ACP" project attach --project /absolute/path/to/project --dry-run --json

  2. Tạo adapter phù hợp project

    Sao chép templates/project.toml, rồi chỉnh:

    • project_id và tên worker_profile;
    • file chỉ dẫn/context cần được worker đọc;
    • protected path, high-risk path, số file/dòng, patch bytes, số vòng sửa;
    • validation profile, path match, cwd, argv, env và timeout;
    • validation_isolation đúng với cách validator thật sự chạy.
    "$ACP" project attach \
  --project /absolute/path/to/project \
  --template /absolute/path/to/project-adapter.toml \
  --dry-run --json

  3. Attach thật

    "$ACP" project attach \
  --project /absolute/path/to/project \
  --template /absolute/path/to/project-adapter.toml --json

  4. Human review và commit adapter

    Người dùng kiểm tra .agentctl.toml và mọi file instruction/context, sau đó commit chúng vào project. Các lệnh Git sau là trách nhiệm của người dùng, không phải thao tác mà agentctl thực hiện:

    git status --short
sed -n '1,260p' .agentctl.toml
git diff -- AGENTS.md
git add .agentctl.toml AGENTS.md
git diff --cached
git commit -m "chore: attach agent control plane"

    run init đòi worktree sạch, base_sha bằng HEAD, và mọi context bắt buộc đã nằm trong commit gốc. Vì vậy attach xong nhưng chưa commit thì chưa chạy task được.

  5. Doctor

    "$ACP" doctor --project /absolute/path/to/project --json

    doctor kiểm tra config, cleanliness, context trong base, executable của validator và worker probe. Hai declaration unsafe-host luôn được báo non-green có chủ đích; chỉ tiếp tục sau khi hiểu và cho phép các unsafe flag tương ứng.

Detach có điều kiện

project detach chỉ xóa config chưa bị sửa kể từ lúc attach, có receipt, và không có run đang active. Evidence cũ vẫn được giữ. Luôn dùng --dry-run trước.

5. Viết task contract nhỏ và kiểm chứng được

Sol bắt đầu từ templates/task.json. Task bị khóa theo hash khi run được tạo; worker không được thay đổi contract.

Không đóng băng sự mơ hồ

Nếu còn câu hỏi làm thay đổi hành vi sản phẩm, security/privacy, data shape, dependency hoặc release scope, Sol dừng và hỏi người dùng trước. Task không chứa provider/model, CLI flags, credential hay suy luận ẩn.

schemas/plan.schema.json có thể dùng để biểu diễn kế hoạch nhiều unit, nhưng CLI hiện tại khởi tạo từng task JSON; không có lệnh agentctl plan.

6. Chạy một vòng hoàn chỉnh

Luôn đọc JSON output và giữ chính xác run_id do controller trả về.

verify_failed → dispatching
Vòng sửa cơ học; evidence lỗi tự được đưa vào request tiếp theo.
repair_queued → dispatching
Sol đã review và yêu cầu sửa semantic có giới hạn.
human_required → accepted
Chỉ sau human approval gắn đủ hash.
reviewing → replan_required
Contract/base mới; run hiện tại kết thúc.
failed / cancelled
Terminal state; không tự coi là thành công.

  1. Khởi tạo run

    "$ACP" run init \
  --project /absolute/path/to/project \
  --task /absolute/path/to/task.json --json

    Nếu profile worker được khai báo unsafe-host và người dùng đã cho phép rõ ràng:

    "$ACP" run init \
  --project /absolute/path/to/project \
  --task /absolute/path/to/task.json \
  --allow-unsafe-worker --json

    Gán giá trị run_id trả về thành RUN_ID.

  2. Dispatch đúng một worker unit

    "$ACP" unit dispatch \
  --project /absolute/path/to/project \
  --run "$RUN_ID" --json

    Controller tạo clone độc lập ở đúng base SHA, bỏ remote origin, rồi giới hạn thời gian/output. Khi chụp patch, controller dùng Git metadata nông do chính nó sở hữu và chỉ trỏ work tree vào file của worker; commit, index hoặc .git/config do worker sửa không thể che patch.

  3. Verify

    "$ACP" unit verify \
  --project /absolute/path/to/project \
  --run "$RUN_ID" --json

    Nếu validator là unsafe-host và đã được human cho phép:

    "$ACP" unit verify \
  --project /absolute/path/to/project \
  --run "$RUN_ID" \
  --allow-unsafe-validation --json

    Verifier kiểm tra allowed/forbidden/protected paths, ngân sách file/dòng/bytes, binary/symlink, validation coverage và chạy argv đã chọn trong clone tươi. Nếu validator sửa patch được review, evidence bị đánh fail.

  4. Theo dõi hoặc hủy

    "$ACP" run status --project /absolute/path/to/project --run "$RUN_ID" --json
"$ACP" run status --project /absolute/path/to/project --json
"$ACP" run cancel --project /absolute/path/to/project --run "$RUN_ID" --json

    Khi worker/verifier đang chạy, cancel trả cancel_requested; poll status cho tới khi process dừng.

7. Review, human gate và tích hợp

  1. Tạo review pack sau khi evidence xanh

    "$ACP" review pack \
  --project /absolute/path/to/project \
  --run "$RUN_ID" --json

    Mở đúng path review_pack được trả về. Sol chỉ review task, patch, evidence, invariants và uncertainty trong pack; không dùng worker transcript làm chứng cứ.

  2. Chọn đúng một decision

    DecisionKhi nào dùngĐiều kiện quan trọng
    acceptMọi tiêu chí đạtĐủ chính xác mọi acceptance ID; không blocker/major; không high-risk file/flag
    repairContract vẫn đúng, lỗi sửa gọn đượcÍt nhất một finding blocker/major và còn budget
    replanCần đổi objective/scope/base/dependencyTạo task/run mới; không lách bằng sửa contract cũ
    human_requiredEvidence xanh nhưng cần thẩm quyền/rủi ro caoHuman phải duyệt đúng patch và toàn bộ hash

    Mọi decision khác accept phải có ít nhất một finding hành động được; riêng repair bắt buộc có finding mức blocker hoặc major.

    Bắt đầu từ templates/review.json, chép đúng các hash trong state/pack và viết finding cụ thể: ID, severity, failure mode, required change.

  3. Submit review

    "$ACP" decision submit \
  --project /absolute/path/to/project \
  --run "$RUN_ID" \
  --file /absolute/path/to/review.json --json

    Patch thay đổi một byte cũng làm quyết định cũ vô hiệu. Không sửa hash bằng tay để vượt gate.

  4. Nếu cần human approval

    Human mở task/patch/evidence/review đã khóa, điền templates/human-approval.json với patch_sha256, task_sha256, evidence_sha256, review_sha256, identity và rationale thật. approved_by phải là identifier dạng [a-z0-9][a-z0-9._-]{0,127}, ví dụ truongphuhung, không phải display name hay email:

    "$ACP" decision approve-human \
  --project /absolute/path/to/project \
  --run "$RUN_ID" \
  --file /absolute/path/to/human-approval.json --json

  5. Dry-run integration trước

    "$ACP" integrate \
  --project /absolute/path/to/project \
  --run "$RUN_ID" --dry-run --json

    Nếu không ghi --dry-run hay --apply, mặc định vẫn là dry-run. Project phải có worktree sạch và HEAD đúng base SHA đã review.

  6. Chỉ apply khi human đã cho phép

    "$ACP" integrate \
  --project /absolute/path/to/project \
  --run "$RUN_ID" --apply --json

    Kết quả ghi rõ committed: false và pushed: false. Human xem diff, chạy check bổ sung nếu cần, rồi tự stage/commit/push/merge/deploy theo quy trình project.

Những việc agentctl không bao giờ làm

Không commit. Không push. Không merge. Không deploy. Nó có thể áp patch vào worktree khi nhận --apply, và validator có thể chạy bất kỳ argv nào project đã cấu hình — vì thế phải review config và isolation trước.

8. Ví dụ với social_match

Adapter đã chuẩn bị cho project này dùng profile default-implementer, context kiến trúc/yêu cầu, protected/high-risk paths hẹp và các validation profile docs, client, server, vertical-slice, migration, containers.

8.1 Hoàn tất attach policy

PROJECT=/absolute/path/to/social_match
"$ACP" project inspect --project "$PROJECT" --json
git -C "$PROJECT" status --short
sed -n '1,320p' "$PROJECT/.agentctl.toml"
git -C "$PROJECT" diff -- AGENTS.md

Nếu .agentctl.toml và AGENTS.md chưa nằm trong HEAD, human cần review rồi commit chúng. Không khởi tạo task khi worktree còn dirty. Sau đó:

"$ACP" doctor --project "$PROJECT" --json
Đọc kết quả doctor đúng ngữ cảnh

Máy chưa có mix sẽ báo các server validator không khả dụng, kể cả task docs. Adapter hiện khai báo validation unsafe-host, và profile OpenCode trực tiếp cũng thường là unsafe-host; hai check isolation vì vậy non-green có chủ đích. Cài tool còn thiếu hoặc dùng sandbox thật, và chỉ dùng unsafe flags sau khi human cho phép.

8.2 Task docs nhỏ, đặt ngoài repository

Tạo một JSON ngoài worktree (ví dụ trong thư mục tạm), thay SHA bằng đúng git -C "$PROJECT" rev-parse HEAD:

{
  "contract_version": 1,
  "task_id": "clarify-match-rule",
  "base_sha": "CURRENT_SOCIAL_MATCH_HEAD_SHA",
  "objective": "Clarify one approved match rule in requirements without changing behavior.",
  "acceptance": [
    {
      "id": "ac1",
      "claim": "The existing rule is unambiguous and adds no new behavior.",
      "proof": "diff"
    }
  ],
  "non_goals": ["No runtime code changes", "No new product policy"],
  "context_files": ["docs/product/requirements.md"],
  "allowed_paths": ["docs/product/requirements.md"],
  "forbidden_paths": ["AGENTS.md", ".agentctl.toml", ".github/**", ".env*", "**/.env*"],
  "validation_profiles": ["docs"],
  "risk_flags": [],
  "budget": {"wall_seconds": 900, "max_fix_rounds": 1}
}

8.3 Chạy theo protocol

"$ACP" run init --project "$PROJECT" --task /absolute/path/to/task.json \
  --allow-unsafe-worker --json

# Đặt RUN_ID bằng giá trị JSON vừa trả về.
"$ACP" unit dispatch --project "$PROJECT" --run "$RUN_ID" --json
"$ACP" unit verify --project "$PROJECT" --run "$RUN_ID" \
  --allow-unsafe-validation --json
"$ACP" review pack --project "$PROJECT" --run "$RUN_ID" --json

Hai unsafe flag trong ví dụ chỉ hợp lệ sau khi người dùng đã chấp nhận chạy trực tiếp trên host. Nếu đã bọc cả worker lẫn validator bằng sandbox thật và khai báo đúng external-sandbox, bỏ hai flag này.

9. Doctor và xử lý sự cố

dirty_worktree, config_in_base: false, context_not_in_base

Adapter/context chưa được commit hoặc worktree còn thay đổi. Human xác định chính xác thay đổi cần giữ, commit chúng, lấy HEAD mới và tạo lại task. Không tự reset hay xoá việc của người khác.

worker_profile_not_found hoặc worker_unavailable

Đồng bộ tên profile giữa .agentctl.toml và user config; kiểm tra path từ agentctl paths, PATH, probe_argv, Python/OpenCode. Có thể dùng --user-config /path/config.toml khi cần config khác.

Probe xanh nhưng model/provider vẫn lỗi

Probe template chạy unfiltered opencode models và kiểm tra probe_contains. Chạy thêm opencode auth list và opencode models --refresh, rồi chép chính xác ID do runtime in. Doctor không xác minh auth, network hay chất lượng sandbox.

unsafe_worker_requires_opt_in / unsafe_validation_requires_opt_in

Đây là gate chủ ý. Tốt nhất dựng external sandbox. Nếu human chấp nhận host execution, thêm đúng flag ở đúng bước. Flag không tăng mức cô lập.

unknown_validation_profile / no_profiled_validation_for_path

Task yêu cầu profile chưa tồn tại, hoặc file thay đổi không được command nào trong profile bao phủ. Sửa task/config ở một base mới thay vì bỏ qua validation.

verify_failed

Mở evidence.json và log path/hash trong run root. Nếu là lỗi cơ học có phạm vi rõ và còn budget, dispatch lại; controller tự đưa evidence lỗi vào repair context. Không tạo review pack khi evidence chưa xanh.

config_drift, patch_drift, artifact_tampered, review_mismatch

Dừng ngay. Không sao chép/sửa hash để vượt gate. Khôi phục artifact đúng hoặc tạo run mới từ base sạch. Mọi thay đổi patch làm review cũ mất hiệu lực.

base_sha_drift khi integrate

HEAD project đã khác commit được review. Không áp patch cũ lên base mới; tạo task/run mới để evidence và decision gắn đúng code hiện tại.

Timeout, output limit hoặc exit code 127

Dùng run status --run lấy run_root, đọc worker/verifier result và log. Exit 127 thường là executable không có; timeout/output limit cần thu nhỏ task hoặc sửa runtime/command. Không coi log thiếu là pass.

Báo lỗi mà không làm lộ secret

Gửi error code, run ID, base SHA, patch SHA và tên check thất bại. Không gửi API key, auth store, raw environment hay log chưa kiểm tra.

10. Checklist trước khi bấm chạy

  • Project adapter và mọi instruction/context đã được human review + commit.
  • Worktree sạch; task base SHA đúng bằng HEAD.
  • Model ID được xác nhận bằng opencode models, không đoán theo tên marketing.
  • Credential nằm ngoài repository/task/prompt.
  • Worker và validator có sandbox thật; nếu không, human đã cho phép rõ hai unsafe flag.
  • OpenCode permission chặn external directory, commit/push và capability không cần thiết.
  • Task có một objective, đường dẫn hẹp, tiêu chí có proof và budget hữu hạn.
  • Sol chỉ review frozen pack và mọi decision gắn đúng hash.
  • High-risk patch đi qua human_required và approval thật.
  • integrate --dry-run đạt trước --apply; human giữ quyền Git/release.
